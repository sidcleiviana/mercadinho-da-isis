# Interface do Usuário

**Documento:** 04_INTERFACE.md

---

# 1. Objetivo

A interface deverá permitir que uma criança utilize o sistema com facilidade, autonomia e segurança.

O sistema deve parecer um software profissional simplificado, e não um jogo.

Toda decisão visual deve favorecer clareza e organização.

---

# 2. Filosofia Visual

A interface deverá transmitir a sensação de um pequeno supermercado.

Não utilizar:

* personagens;
* mascotes;
* animações exageradas;
* efeitos sonoros constantes;
* elementos piscando;
* recompensas visuais;
* excesso de cores.

O foco sempre deverá ser a operação do mercado.

---

# 3. Aparência

A identidade visual deverá ser limpa.

Preferências:

* fundo rosa claro;
* boa iluminação visual;
* cantos arredondados;
* sombras discretas;
* ícones simples;
* fotografias dos produtos.

A interface deve parecer moderna.

---

# 4. Navegação

O usuário nunca deverá ficar perdido.

Sempre deverá existir um menu principal.

Sugestão:

* Dashboard
* Caixa
* Produtos
* Estoque
* Relatórios
* Configurações

O acesso às telas deverá ocorrer com apenas um clique.

---

# 5. Dashboard

O Dashboard é a tela inicial.

Ele representa o estado atual do mercado.

Deverá conter:

* Nome do mercado
* Situação do mercado
* Botão Abrir Mercado
* Botão Fechar Mercado
* Clientes aguardando
* Saldo do caixa
* Produtos em estoque
* Última venda
* Notificações

O Dashboard deve responder rapidamente às principais perguntas:

"O mercado está aberto?"

"Existe alguém esperando?"

"Quanto dinheiro existe no caixa?"

---

# 6. Abrir Mercado

Quando o mercado estiver fechado:

O Dashboard deverá destacar um grande botão:

**Abrir Mercado**

Ao abrir o mercado:

* inicia um novo dia;
* gera os clientes virtuais daquele dia;
* sorteia horários de chegada;
* inicia o relógio interno;
* habilita as notificações.

---

# 7. Fechar Mercado

Ao fechar o mercado:

* nenhum novo cliente poderá aparecer;
* atendimentos pendentes serão encerrados;
* será exibido um resumo do dia.

Resumo:

* clientes atendidos;
* clientes desistentes;
* vendas realizadas;
* valor vendido;
* saldo do caixa.

---

# 8. Notificações

As notificações deverão ser discretas.

Quando um cliente chegar:

Uma notificação deverá aparecer imediatamente.

Exemplo:

"Novo cliente aguardando atendimento."

Ao clicar na notificação:

Abrir diretamente a Central de Atendimento.

---

# 9. Central de Atendimento

Esta é uma das telas principais do sistema.

Ela deverá apresentar:

* clientes aguardando;
* clientes em atendimento;
* clientes finalizados;
* clientes desistentes.

Cada atendimento deverá possuir um botão:

**Atender**

Ao iniciar o atendimento:

Abrir a conversa do cliente.

---

# 10. Conversa

A conversa deverá possuir aparência semelhante a um chat.

O cliente envia mensagens.

A criança responde apenas utilizando botões.

Nunca utilizar campo para digitação.

As respostas disponíveis dependerão do contexto da conversa.

---

# 11. Venda

Durante o atendimento:

O sistema deverá mostrar:

* produtos solicitados;
* quantidade;
* produtos já registrados;
* valor parcial;
* valor total.

A leitura do código de barras deverá atualizar essas informações em tempo real.

---

# 12. Leitor de Código de Barras

Sempre que um produto for lido:

O sistema deverá:

* localizar o produto;
* exibir sua foto;
* exibir seu nome;
* confirmar visualmente a leitura;
* atualizar a venda.

A resposta deverá ser imediata.

---

# 13. Produtos

A tela de produtos deverá apresentar:

* fotografia;
* nome;
* categoria;
* preço;
* quantidade em estoque.

A pesquisa deverá permitir localizar produtos rapidamente.

---

# 14. Cadastro de Produto

O formulário deverá possuir:

Foto

Nome

Categoria

Código de Barras

Preço

Botão Salvar

O cadastro deverá ser simples e intuitivo.

---

# 15. Estoque

A tela de estoque deverá destacar:

* fotografia;
* nome;
* quantidade disponível.

Sempre que possível:

Produtos com estoque baixo deverão ser destacados visualmente.

Sem alarmes.

Sem animações.

Apenas diferenciação discreta.

---

# 16. Caixa

A tela do caixa deverá apresentar:

Saldo Atual

Entradas

Saídas

Histórico

Cada movimentação deverá indicar:

* data;
* horário;
* descrição;
* valor.

---

# 17. Relatórios

Os relatórios deverão ser simples.

Utilizar:

* gráficos;
* indicadores;
* tabelas.

Evitar excesso de informações.

Priorizar compreensão rápida.

---

# 18. Responsividade

Todo o sistema deverá funcionar corretamente em:

* notebook;
* tablet.

A interface deverá adaptar automaticamente seu layout.

---

# 19. Botões

Todos os botões importantes deverão possuir tamanho adequado para toque.

Os textos deverão ser claros.

Exemplos:

Abrir Mercado

Fechar Mercado

Atender

Cancelar

Finalizar Venda

Adicionar Estoque

Salvar

---

# 20. Feedback

Toda ação importante deverá gerar retorno visual.

Exemplos:

Produto encontrado.

Produto não encontrado.

Venda concluída.

Estoque atualizado.

Cliente desistiu.

Mercado aberto.

Mercado fechado.

Esses retornos deverão ser discretos e desaparecer automaticamente após alguns segundos.

---

# 21. Acessibilidade

Utilizar:

* bom contraste;
* fontes legíveis;
* botões grandes;
* espaçamento adequado.

Evitar depender exclusivamente de cores para transmitir informações.

---

# 22. Objetivo Final

Ao utilizar o sistema, a criança deve sentir que está operando um pequeno supermercado real.

A interface deve desaparecer durante o uso, permitindo que toda a atenção fique voltada para o atendimento dos clientes, o controle do caixa e a organização do estoque.
